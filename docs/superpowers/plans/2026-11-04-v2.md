# Stonerspots 2.0

**Goal:** turn the map-and-feed app into a community app. 1.x lets people add
spots, post updates, rate and save spots. In 2.0 people can also find each
other, follow each other, talk under updates and hear when something happens
to their own content. Two practical additions: finding a spot by name and
seeing the weather before going out.

Branch: `v2` (kept apart from `main` until it is approved).

## Scope

1. **Public profiles and following**
   - API: `GET /users/{id}` (display name, joined date, counts: spots, updates,
     followers, following; `following: bool` for the caller),
     `GET /users/{id}/spots`, `GET /users/{id}/updates` (cursor paging like the
     feed), `PUT /users/{id}/follow`, `DELETE /users/{id}/follow`.
     Banned or deleted users answer 404. Migration `0020_follows`.
   - Feed: `GET /feed?following=true` shows only updates of people the
     caller follows (401 without login).
   - App: tapping an author name (feed card, update tile, review) opens
     `/user/:id`; follow / unfollow button; feed header gets a
     "Following" filter when logged in.

2. **Comments on updates**
   - API: `GET /updates/{id}/comments` (oldest first, cursor paging),
     `POST /updates/{id}/comments` (text 1..500 chars, quota per day),
     `DELETE /comments/{id}` (author or admin); updates carry `comment_count`.
     Comments can be reported through `POST /reports` (target `comment`).
     Migration `0021_comments`.
   - App: comment button with count on feed cards and update tiles; a sheet
     with the thread and a composer; delete own comment.

3. **Spot search and weather**
   - API: `GET /spots/search?q=` (name match, DACH, max 20, nearest first when
     `lat`/`lon` are given). Migration `0022_spot_name_index` if an index
     is needed.
   - App: search field in the map chrome; picking a result flies the map to
     the spot and opens its card. Spot page shows current weather and the next
     hours from Open-Meteo (no key; coordinates of a public spot only).

4. **Activity** (after 1-3 are merged)
   - API: `GET /me/activity` (someone followed you, commented on your update,
     liked/rated your spot), `POST /me/activity/read`; unread count in `/me`.
     Migration `0023_activity`.
   - App: bell on the profile tab with an unread badge, an Activity page.

5. Version `2.0.0+2`, "What's new in 2.0" in settings.

## Rules

- Every new string in German (template) and English ARB files, regenerate
  with `flutter gen-l10n`.
- Backend tests against the dev MariaDB (`make test`), `flutter analyze` and
  `flutter test` green before merge.

## Note: shipped as 1.0.0

There was never a published 1.x release (only `dev-<n>` builds), so the
first real release of this work is **1.0.0**, not 2.0: `app/pubspec.yaml`
says `1.0.0+1` and settings show "What's new in 1.0" with all main
features. The plan above stays as written. Release process: README,
"Releasing 1.0"; contents: `CHANGELOG.md`.
